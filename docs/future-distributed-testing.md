# 后续多机测试与远程桌面架构

状态：规划，当前迁移和源码验收没有实现这里的局域网发现、跨机派单、屏幕共享、远程控制或弱网模拟，也没有验证这些功能的可用性。这里不是当前能力清单。

各机器运行同一 Project Workbench 和测试插件。每台可自行设置、修改局域网显示名；显示名仅用于区分，不是设备身份。发现只展示候选设备，不能授予访问权限；设备身份应由独立密钥及经过核验的配对绑定。B/C/D 各自授权指定 A，可撤销或停止；授权应分别覆盖派发测试、查看当前桌面和发送控制输入，并细化到目标、动作、有效期与并发范围。可持久授权允许范围内后续操作不再逐次确认，必须在 B 可见当前共享、控制及停止入口。撤销应终止或拒绝对应会话，身份失效不能自动重新授权。

A 可向多台已授权设备提交任务，每台独立排队和隔离执行，回传有界进度、结果及证据；任务和设备的身份、状态和结果必须关联，不能把不同设备的结果混在一起。取消、断线、执行中止及结果未知需明确区分；不能因断线盲目重放可能已执行的动作。支持去重标识与可查询的任务状态，必要时由人决定是否重新执行。授权撤销、任务取消和远程输入同时发生时，应先停止接收新的动作并等待已接受工作的明确终态。

远程画面与操作集成在工作台内，多机可切换画面；查看和控制分别授权，同一被控会话的输入需要互斥，交接、断线和取消均应释放控制权。锁屏、UAC 安全桌面、用户会话切换及受保护内容受 Windows 限制，后续需在隔离机器上验证并明确不可用状态，不承诺绕过系统安全边界。传输和身份认证需要加密、设备密钥核验、重放防护与审计；技术选型、开源许可和依赖维护风险仍待验证。

弱网、断网和恢复统一出现在测试模块界面内，手动操作和自动化任务可调用同一内部模块；普通测试不依赖启动模拟。范围必须限定经授权设备上的指定应用及生效时段，显示当前策略与结果，提供明确停止、失联后的恢复和故障报告，并保护用于撤销的控制通道。某些实现可能需要特权或驱动，应先完成 Windows 方案和权限设计；不默认以管理员身份启动整个工作台，也不擅自安装驱动、修改防火墙或系统网络设置。

建议按可验证的最小闭环分阶段推进：先做本地身份和授权模型，再做隔离环境内的发现与安全连接、有限任务派发和状态回传；随后分别验证画面观看、独占控制，以及应用隔离的网络模拟。每一步都保留清晰的未实现和平台限制提示；任务界面不采用拖拽节点流程编辑器。
