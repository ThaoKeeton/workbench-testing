# Verification after repository migration

This repository starts from Project Workbench source commit `655d7b6496067daad7c5e4cefb1f1da1b8379536`. Earlier monorepo build and runtime results are historical evidence only. They do not establish that this independently built package works.

The public build workflow runs business tests on Linux and Windows, explicit Linux reference compilation, Windows MSVC helper construction, audited ZIP packaging, real host package-store installation, native panel/process restore, and an owned synthetic-target UIA/capture probe. Only a successful exact-commit Windows run uploads a native plugin delivery. `provenance.json` records the testing repository commit separately from the pinned host commit, SDK package hashes, native helper identity, source hashes, payload hashes, and ZIP SHA256. Every run must be checked separately.

Linux reference-only output cannot become a native ZIP. Windows Server automatic probes, including a green `source-cross-windows` job, do not establish Windows 11 24H2+ x64 manual picker, IME, theme, DPI, accessibility, real devices, live Figma/OpenAI, Webhook, or DingTalk acceptance. Re-check a retained cross-acceptance bundle with `scripts/verify-cross-acceptance-evidence.py` before treating its bytes as still available; artifacts expire after seven days. No real accounts, credentials, webhooks, or user project roots are supplied by CI. Remote source tests use synthetic credentials and injected in-memory HTTP only.

The host SDK, Core service implementations, host storage contracts, SDK compatibility tests, and host native diagnostic tests remain owned by `project-workbench`. A pinned external checkout is used only as SDK source and as a test fixture. There is no bundled host executable or SDK/Core assembly in the eight-file plugin ZIP.
