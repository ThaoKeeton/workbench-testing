# 局域网多机测试与工作台内远程桌面：需求草案

状态：后续规划，当前测试插件迁移没有实现此功能，也未连接任何用户电脑。

## 使用方式

A、B、C、D 均运行同一个 Project Workbench 与测试插件；每台工作台可由使用者设置、修改一个局域网显示名称。名称和 IP 只是帮助识别，不能作为认证身份。发现到设备不等于有权访问；网络发现需要明确启用，手动指定地址可作为发现失败时的备选，不自动修改防火墙、路由器或系统网络设置。

A 能同时向多个已授权节点派发测试，在列表中查看每台机器的排队、运行、离线、取消、失败和完成状态，并分别查看结果与证据。工作台内提供多画面预览、切换和放大，无需跳转独立远程桌面软件；节点、测试与结果采用列表和详情界面，不需要拖拽式流程编辑器。

## 设备身份与授权

建议每台设备保存独立、长期的设备密钥；首次配对由 B 本机明确核对 A 的身份指纹并授权，连接使用加密和双向身份验证。发现广播仅用于寻找候选设备，名称相同、地址变化或被冒充都不能自动继承授权。

B 对指定的 A 分别授予测试派发、画面观看、键鼠控制权限；授权可限制目标应用、允许的动作、有效期与其他范围。授权范围内不要求 B 对每一次派发重复确认；未经授权的权限或越界请求仍须拒绝。B 界面持续显示共享、观看、控制和运行状态，并可随时停止或撤销授权，撤销后终止相应会话和权限。测试证据、日志和屏幕图像不得默认进入公开仓库。

## 调度与断线

A 分别向每台 B/C/D 发送带任务 ID、目标和限定动作的请求；各节点独立排队、限制并发并回传进度和结果。远程键鼠控制对同一桌面使用互斥租约，避免多个 A 同时操控；B 本机停止优先。任务确认、运行、取消和结果持久化应能区分：已接收、执行中、确定完成、已取消及状态未知。

断网、重启或撤销时不得盲目重放可能产生副作用的动作。重连后按任务与尝试标识先对账；不能证明结果时显示待核实，由用户决定下一步。每项权限、操作、状态变化及错误保留必要审计信息，避免写入凭据或不必要的屏幕内容。

## Windows 边界

画面采集与输入仅在 B 已登录、可交互且授权的会话内运行。锁屏、用户退出、UAC 安全桌面或其他操作系统保护导致画面/输入不可用时，应如实暂停或显示不可用，不绕过系统安全边界，不自动输入用户密码。不同 Windows 版本、会话切换、网络波动及多显示器行为需分别验证。

## 技术候选与许可证核对

- Windows 的 [Graphics Capture API](https://learn.microsoft.com/en-us/windows/apps/develop/media-authoring-processing/screen-capture) 可获取显示器或窗口画面，并有系统选择与捕获提示；具体 WinUI 集成和持续授权体验仍需实测。
- Windows [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput) 受 UIPI 完整性级别约束，不能据此承诺控制更高权限的窗口，也不应绕过系统限制。
- [WebRTC 原生项目](https://webrtc.googlesource.com/src/+/refs/heads/main/LICENSE) 采用 BSD 风格许可证，可作为画面/数据传输候选；具体绑定、编解码器、第三方依赖及其许可证必须在选型时逐项核查。
- [libdatachannel](https://github.com/paullouisageneau/libdatachannel) 是支持数据通道和媒体传输的 C/C++ 候选，项目标注 MPL-2.0；需评估其依赖和 WinUI/C# 集成成本。
- [RustDesk](https://github.com/rustdesk/rustdesk) 是可研究的开源远程桌面实现，但项目标注 AGPL-3.0；不能假设可直接复制或链接而无许可证义务。上述都只是候选，尚未选定、集成或验证。

## 指定应用的网络条件模拟

后续网络环境模拟放在测试模块的统一界面，不单独安装插件；内部保持模块化，供手动和自动化调用，普通测试不要求启用网络模拟。它对获授权节点上的指定应用提供弱网、断网和恢复，并报告目标、状态、开始/结束和恢复结果。整个工作台不默认以管理员身份启动，也不默认修改系统网络；需要管理员权限、驱动、防火墙或系统策略的路径必须先单独征得明确授权。程序退出、崩溃、节点重启或撤权后要有可验证的恢复方案，不能误伤其他应用或工作台控制连接。

[Toxiproxy](https://github.com/Shopify/toxiproxy) 使用 MIT 许可证，可作为首个可控 TCP 服务的延迟、带宽或断线测试候选；仅覆盖实际被配置为经过该代理的连接，不能假设能透明控制任意应用或 UDP。[Windows Filtering Platform](https://learn.microsoft.com/en-us/windows/win32/fwp/about-windows-filtering-platform) 支持按应用身份筛选，实际策略权限、细粒度弱网与驱动需求需进一步验证；[ALE 应用身份](https://learn.microsoft.com/en-us/windows/win32/fwp/application-layer-enforcement--ale-)基于规范化文件名，不能自动等同于只影响某一个进程实例。[WinDivert](https://github.com/basil00/WinDivert/blob/master/README) 是包含驱动的候选，项目说明提供 LGPLv3 或 GPLv2 选择，需核验实际版本、签名、权限、进程归属与许可证义务。上述均未集成或在用户设备验证。

建议验证先使用隔离的合成服务和两个测试客户端：只让一个客户端走代理，测量延迟、带宽和断连，验证另一客户端及控制通道不受影响；随后测试手动与自动化调用、取消、崩溃、重启及恢复。要声称透明影响任意 Windows 应用前，还必须单独验证 TCP/UDP、IPv4/IPv6、同可执行文件的多个进程、现存连接、授权撤销和故障清理。

## 建议边界与推进顺序

工作台宿主负责设备身份、发现、授权、加密连接和共享界面等可复用能力；测试插件负责测试任务、执行、结果、证据与测试专用界面。未来如需扩展公共 SDK，应单独版本化并保留现有插件 ID、API 和 schema 的兼容验证。

先完成当前独立仓库迁移及新旧宿主验收，再依次设计设备配对、任务与进度、内嵌观看、授权控制以及多节点故障恢复。此草案是待评审的架构方向，并非现有可用能力或已验证的技术实现。
