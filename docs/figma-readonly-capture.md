# Retained Figma project import backend

`Workbench.Testing.Domain.Sources.Figma` provides a bounded backend read and manual source builder; `TestingController.ImportFigmaAsync` retains that work through project publication. The [native testing page](testing-plugin.md) now exposes explicit imports with file key/version, per-node criteria and the host's protected project credential UI. Verification uses synthetic tokens, in-memory HTTP and real Core project stores. The new remote controls have reference-compile evidence; their actual Windows exercise and live Figma access remain unverified. Existing SDK/host/plugin ABI and development versions are unchanged. Manifest capabilities now include `remote-figma-read` and `openai-case-authoring` as descriptive hints, not enforced permissions or a sandbox; the Domain additions below are explicit.

```csharp
FigmaReadRequest(string FileKey, IReadOnlyList<string> NodeIds, string? Version = null)
FigmaFileReader(HttpMessageHandler? handler = null)
Task<FigmaCapture> ReadAsync(FigmaReadRequest request,
    Func<CancellationToken, Task<string?>> getToken,
    CancellationToken cancellationToken = default)
TestSourceDraft FigmaSourceBuilder.CreateDraft(FigmaCapture capture,
    IReadOnlyDictionary<string, IReadOnlyList<string>> acceptanceCriteria)
TestingController(IPluginTestingContext context, IControlledTestAdapter? adapter = null)
TestingController(IPluginTestingContext context, IControlledTestAdapter? adapter, FigmaFileReader reader)
Task<TestSourceSnapshot> ImportFigmaAsync(FigmaReadRequest request,
    IReadOnlyDictionary<string, IReadOnlyList<string>> acceptanceCriteria,
    Func<CancellationToken, Task<string?>> getToken,
    CancellationToken cancellationToken = default)
```

The reader captures caller node lists synchronously before any credential work. File keys are 1–128 ASCII alphanumeric characters; 1–16 unique ordinal node IDs use basic decimal:decimal syntax and at most 64 characters. URLs and complex instance paths are unsupported. An optional version is 1–64 valid Unicode characters without whitespace or controls.

Each read issues at most one GET to `https://api.figma.com/v1/files/{key}/nodes?ids={ids}&depth=2`, with escaped values and an optional escaped `version`. Credentials are ASCII visible nonwhitespace strings of 1–4096 characters, sent only as the per-request `X-Figma-Token`. Invalid requests never evaluate the credential callback. The default per-call transport disables redirects, cookies and default credentials. An injected handler is caller-owned test transport; it can execute arbitrary code and is not a security sandbox. The reader disposes its client, response and default handler after actual work settles.

One cooperative 30-second linked deadline includes credential lookup, transport and body reads. Each operation is actually awaited: ignored cancellation keeps the returned task pending until that work settles. Caller cancellation becomes a sanitized `OperationCanceledException`; an elapsed deadline becomes `FigmaReadError.Timeout` after settlement. No retries, polling, URL traversal, images, comments, writes, Webhooks or automatic action inference occur.

Responses require `application/json`, optionally with UTF-8 charset, and no content encoding. Headers are read first; oversized Content-Length is refused before body reading. Streaming reads accept at most 1 MiB plus one overflow-detection byte. JSON has depth at most 32, strict UTF-8 and Unicode, and no duplicate properties at any object level, including unknown data. Bounded unknown API fields remain inert data. Required file name (1–200), version (1–64), requested nodes and document identities must all be present and valid; unavailable, null or extra nodes and version mismatches refuse the whole response. Node names are 1–200, types 1–64, and optional characters 0–4096. Nothing is truncated.

`FigmaCapture` exposes `Request`, `Name`, `Version`, `Nodes` and a defensive `OriginalJson` byte copy. Nodes preserve request order and contain only `Id`, `Name`, `Type`, `Characters`. Collections are read-only and caller inputs are copied. Credentials have no capture field.

The builder requires exactly the ordinal node keys in the capture, with 1–16 nonblank valid Unicode criteria per node, each at most 4096 characters and **at most 200 criteria in total**. Shared internal `FigmaInputCapture.CaptureRequest` and `CaptureCriteria` capture the inputs synchronously. The controller owns its operation before it enumerates caller inputs and copies both inputs before credential lookup or HTTP, so 201 criteria refuse without either. Closed admission evaluates neither inputs nor the credential callback. The standalone reader does not accept criteria.

The controller preserves its original constructor and accepts an injected reader through the three-argument overload. The default reader performs no HTTP during construction. Imports serialize with actual authoring work and use the captured project's testing facade. Caller and context-lifetime cancellation are linked, and before-leave/Stop join actual admitted work: ignored cancellation in a callback or transport keeps the operation and preparation pending until it really settles. These are cooperative waits, with the existing finite-budget host semantics; they do not promise forced cancellation or early root release. The controller does not register or read a secret automatically. The production entry registers `figma-token` metadata at initialization and supplies a captured project-store callback only for the explicit native action. This requires `file_content:read` plus access to the target file; Webhook scopes are unrelated. No real token or account has been tested.

After reading and building, publication admission checks cancellation and closure under the same controller lock as Stop, then calls the facade outside that lock. Standalone Stop winning first refuses publication even if the Core context is open. A publication admitted first remains owned and Stop drains it; it may commit afterward. Core facade Close remains the final host-context admission barrier. A successful store acknowledgment is returned and updates the source summary directly, even if cancellation/Stop arrives later. There is no post-acknowledgment list refresh or cancellation check; a full reread remains an explicit `RefreshAsync` operation.

Drafts use kind `Figma`, provider `figma.rest.nodes.manual-criteria`, provider version `1`, and document identity `fileKey@actualVersion`. Title, node locator and node title come from the observed response. Description labels observed type and characters and must fit 4096 characters or the builder refuses. Criteria are exact defensive copies of caller-supplied text: they are never claimed to have come from Figma. Every `VirtualScenario` is null and rule-generated steps remain manual. Without explicit criteria, no source can be built. Core source revisions cover both raw API bytes and supplied criteria; the raw-byte hash remains separately available.

`FigmaReadException.Error` is one of `InvalidRequest`, `CredentialsUnavailable`, `AuthenticationRefused`, `NotFound`, `RateLimited`, `Unavailable`, `ResponseTooLarge`, `ResponseInvalid`, `Timeout`. Its message is fixed and it has no upstream inner exception. 401/403 map to authentication refusal, 404 to not found, 429 to rate limited and all other failures/redirects to unavailable. Only a 429 integer Retry-After of 0–86400 seconds becomes `RetryAfterSeconds`. Error bodies, reason phrases, URLs and upstream exception text never enter an error or capture. Invalid caller input, including all criteria limits, maps to `InvalidRequest`; HTTP body overflow maps to `ResponseTooLarge`. Inside both synchronous capture and asynchronous reader/builder boundaries, the controller maps `InvalidRequest`/`ResponseInvalid` to existing `InvalidTestSource`, `ResponseTooLarge` to existing `StoreLimitExceeded`, and remaining safe remote errors to `TestingFailed`. No SDK/store error codes were added.

The existing combined generator limit of 200 cases and Core 4 MiB encoded-envelope limit remain authoritative. A legal Figma capture and criteria set can still fail Core publication with `StoreLimitExceeded`; there is no alternative serializer, truncation or cap increase. Capture, HTTP, parsing, criteria and publication failures preserve previous source bytes and accepted dirty draft text. No new record is written before publication admission. This is not a cross-call transaction or rollback guarantee: if a store call fails around its commit point, actual bytes are retained without deletion, automatic retry or an assumption that no commit occurred. Explicit refresh can recover a genuinely committed source after such a failure.

In-memory component and controller tests exercise exact bytes/hash/version and manual provenance, CSV traces, distinct real project roots, input/credential boundaries, malformed and oversized responses, ignored-cancellation settlement, both sides of publication/Stop admission, late cancellation after acknowledgment, safe uncertain-commit handling, the 200/201 boundary and Core envelope/IO failures with retained dirty drafts. They make no live Figma, AI, business-provider or Webhook/message calls and use no real credentials or user-PC control. Windows actual/native/download closure and Windows 11 human acceptance remain required; portable Core tests do not replace them.
